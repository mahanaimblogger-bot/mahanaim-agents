# Arquitectura del proyecto

Con lo que veo en el mapa del repo, tu proyecto es un **pipeline de generación de contenido bíblico** (estudios, recursos, imágenes, audio y video) que persiste todo en **Supabase** y se orquesta desde la CLI. Te lo desgloso por capas:

## 1. Capa de acceso a datos — `src/supabaseClient.js`
Es el núcleo de integración con Supabase. Expone funciones para:
- Resolver libros (`obtenerBookIdPorSlug`) y capítulos (`obtenerOCrearChapterId`, `buscarChapterId`).
- CRUD de recursos (`obtenerRecurso`, `obtenerRecursosPorTipo`, `guardarRecursoComoBorrador`, `guardarRecursoComoPublicado`, `actualizarContenidoRecurso`, `publicarRecurso`, `eliminarRecurso`).
- Lectura de versículos (`obtenerTextoCapituloCompleto`, `obtenerVersiculo`, `obtenerVersiculoPorSlug`).

Todo el resto del sistema depende de este módulo.

## 2. Capa de dominio / lógica de negocio — `src/`
- **`generarEstudio.js`**: orquesta la generación de un estudio (recibe libro, capítulo, video, mínimo de palabras, forzar, indicación manual).
- **`promptsRecursos.js`**: construye los prompts para cada tipo de recurso (con reglas de ortografía, recorte defensivo de fuentes largas, clases CSS).
- **`formateadores.js`**: convierte los JSON devueltos por la IA en HTML para cada tipo de recurso (ilustraciones, citas, quiz, infografía, paralelos, profecías, conexiones AT/NT, cronología, palabras clave). Incluye `escapeHtml` y `limpiarHtml`.
- **`validarEstudio.js`**: valida el HTML generado y agrega tooltips de versículos en prosa (usa `librosBiblia.js` para resolver referencias).
- **`librosBiblia.js`**: mapa de nombres/slugs de libros bíblicos con normalización de tildes y variantes.
- **`aprobarEstudio.js`**: cambia el estado de un estudio a aprobado/publicado.

## 3. Capa de imágenes
- **`extraerImagenesSugeridas.js`**: parsea los comentarios `<!-- IMAGEN_SUGERIDA... -->` del HTML.
- **`listarImagenesPendientes.js`**: lista las imágenes que faltan incorporar.
- **`incorporarImagenes.js`** + **`incorporarImagenesEnHtml.js`**: reemplazan los marcadores por `<img>` reales.

## 4. Capa CLI — `src/cli*.js`
Cada comando tiene su propio entrypoint (`cli.js`, `cliAprobar.js`, `cliImagenesPendientes.js`, `cliIncorporarImagenes.js`). Todos comparten el mismo patrón de parseo de argumentos `--clave=valor`.

## 5. Scripts auxiliares — `scripts/`
- **`construir-base-ilustraciones.js`**: ingesta PDFs/TXT de clásicos (Spurgeon, Moody, etc.), los divide en bloques y los estructura con IA.
- **`generate-prompts.js`**: genera prompts para NotebookLM a partir de los recursos de un capítulo (incluye mapas con Google Maps embed).
- **`generar-imagenes.js` / `regenerar-imagen.js`**: descargan imágenes generadas por IA.
- **`generar-miniatura.js` / `generar-fondo-miniatura.js`**: generan miniaturas con canvas y fondos con fal.ai.

## 6. Capa multimedia
- **`audio-tts/generar-audio.js`**: sintetiza SSML con Google TTS, controla cuota mensual en Supabase (`uso_mensual_tts`), une WAVs y masteriza con ffmpeg.
- **`video/ensamblar-video.js`**: arma el video final con efecto Ken Burns, concatena clips y agrega el audio.

## Flujo general

```
CLI (src/cli*.js)
   └─> generarEstudio.js
         ├─> promptsRecursos.js  (arma prompts)
         ├─> [IA externa]        (genera JSON)
         ├─> formateadores.js    (JSON → HTML)
         ├─> validarEstudio.js   (valida + tooltips)
         └─> supabaseClient.js   (persiste borrador)
   └─> aprobarEstudio.js         (publica)
   └─> incorporarImagenes.js     (reemplaza marcadores)
   └─> audio-tts / video         (derivados del estudio)
```

## 1. `scripts/generate-prompts.js`

**Qué hace:** Es el generador de "prompts para NotebookLM" a partir de los recursos ya guardados en Supabase de un capítulo. Es un módulo **exportable** (`generarPromptsCapitulo(bookSlug, chapterNumber)`) pensado para ser invocado por un orquestador.

**Flujo interno:**
1. `fetchChapterResources` → busca el libro por slug y el capítulo por número en Supabase.
2. `getResourcesForChapter` → trae todos los recursos del capítulo (`estudio`, `sermon`, `bosquejo`, `infografia`, `contexto_arqueologico`, `palabras_clave`, `citas_teologos`, `citas_libros`).
3. `buildPlainTextSource` → arma un `.txt` consolidado (limpia HTML con `cleanHtml`) para subir a NotebookLM.
4. `buildPrompts` → construye 8 prompts distintos:
   - `prompt_video` (estilo visual + narrativo)
   - `prompt_mapa` (mapa mental)
   - `prompt_diapositivas`
   - `prompt_miniatura` (en inglés, para Midjourney/DALL-E)
   - `prompt_descripcion` (SEO YouTube)
   - `prompt_mapa_interactivo` (JSON con ubicaciones geográficas)
   - `prompt_podcast_guion`
5. `generateWithAI` → llama a DeepSeek con `response_format: json_object`.
6. `saveFilesLocally` → escribe archivos numerados `1_VIDEO_...txt`, `2_MAPA_MENTAL_...txt`, etc. en `prompts_output/<libro>/Capitulo_<n>/` con BOM UTF-8.
7. Para el mapa interactivo, `generateMapResourceHTML` genera HTML con `<iframe>` de Google Maps embebido.
8. **Al final** llama a `generarArtefactosVideo` (función interna) que:
   - Genera `prompts_imagenes_video.json` (12 prompts en inglés para Flux/Midjourney).
   - Genera `guion_video_tts.ssml` (guion SSML con 12 marcas `<mark name="imagen_N"/>` para sincronizar con las imágenes).

**Conexiones:**
- **Entrada:** Supabase (`books`, `chapters`, `resources`).
- **Salida:** archivos en `prompts_output/` que consumen los scripts de imágenes, miniatura y video.
- **Depende de:** `@supabase/supabase-js`, `openai` (SDK apuntando a DeepSeek), `fs`, `path`.
- **Es consumido por:** el orquestador (probablemente `src/orquestador-maestro.js`).

## 2. `scripts/generar-fondo-miniatura.js`

**Qué hace:** Genera la **ilustración de fondo** de la miniatura de YouTube usando **fal.ai** (`fal-ai/flux/dev`). No agrega texto: solo la imagen base.

**Flujo:**
1. Lee `prompts_output/<libro>/Capitulo_<n>/youtube_metadata.json`.
2. Extrae `meta.miniatura.prompt_ilustracion`.
3. Llama a `fal.subscribe` con `image_size: 1280x720`, `num_inference_steps: 28`, `guidance_scale: 3.5`.
4. Descarga la imagen resultante y la guarda como `miniatura_fondo.png`.
5. Reintenta 1 vez si falla.

**Conexiones:**
- **Entrada:** `youtube_metadata.json` (generado por el orquestador, no por `generate-prompts.js`).
- **Salida:** `miniatura_fondo.png` → consumido por `generar-miniatura.js`.
- **Depende de:** `@fal-ai/client`, `FAL_KEY` en `.env`.

## 3. `scripts/generar-miniatura.js`

**Qué hace:** Compone la **miniatura final de YouTube** (1280×720, JPG < 2 MB) superponiendo texto sobre la ilustración de fondo, usando `@napi-rs/canvas`.

**Flujo:**
1. Lee `youtube_metadata.json` → `meta.miniatura` (`etiqueta`, `texto_principal`, `texto_secundario`, `lado_texto`).
2. Busca `miniatura_fondo.(png|jpg|jpeg|webp)` en la carpeta del capítulo.
3. Registra la fuente `Anton-Regular.ttf` desde `assets/fonts/`.
4. Compone:
   - Fondo con `cover` + filtro `contrast/saturate`.
   - Degradado lateral + viñeta.
   - Etiqueta superior ("ESTUDIO DE <LIBRO> <CAP>").
   - Texto principal grande con relieve 3D y contorno negro.
   - Franja roja inclinada con texto dorado (complemento).
5. Ajusta tamaño de fuente dinámicamente (`ajustar`) para que quepa en 1 o 2 líneas.
6. Exporta JPG bajando calidad hasta quedar bajo 1.9 MB.

**Conexiones:**
- **Entrada:** `youtube_metadata.json` + `miniatura_fondo.png`.
- **Salida:** `miniatura.jpg` (lista para subir a YouTube).
- **Depende de:** `@napi-rs/canvas`, `assets/fonts/Anton-Regular.ttf`.
- **Acepta overrides por CLI:** `--fondo`, `--principal`, `--secundario`, `--etiqueta`.

## 4. `video/ensamblar-video.js`

**Qué hace:** Ensambla el **video final** (MP4) a partir de las imágenes generadas + el audio TTS, con efecto **Ken Burns** (zoom/pan) por imagen.

**Flujo:**
1. Detecta FFmpeg portable en `tools/ffmpeg/...` (solo Windows).
2. Lee:
   - `audio-tts/guion_video_tts_final.mp3`
   - `audio-tts/guion_video_tts_timestamps.json` (marcas `imagen_N` → segundos)
   - `prompts_output/<libro>/Capitulo_<n>/imagenes/imagen_N.(png|jpg|webp)`
3. Calcula duración de cada imagen a partir de las marcas (la última se ajusta a la duración real del audio vía `ffprobe`).
4. `generarClipKenBurns` → por cada imagen, aplica `zoompan` en 3 fases (apertura rápida → pausa → zoom lento → cierre rápido) a 1920×1080, 24 fps, H.264.
5. `concatenarClips` → usa `concat` demuxer con `-c copy`.
6. `agregarAudio` → mezcla el MP3 con `-c:a aac -b:a 192k -shortest`.
7. Limpia temporales.

**Conexiones:**
- **Entrada:** audio TTS + timestamps + imágenes.
- **Salida:** `prompts_output/<libro>/Capitulo_<n>/video/video_final.mp4`.
- **Depende de:** `fluent-ffmpeg`, FFmpeg (portable o del sistema).
- **Consume indirectamente:** las marcas `<mark name="imagen_N"/>` que genera `generate-prompts.js` en el SSML, y los `prompts_imagenes_video.json` que alimentan a `scripts/generar-imagenes.js`.

## 5. `src/supabaseClient.js`

**Qué hace:** Es la **única capa de acceso a Supabase**. Todo el resto del sistema pasa por acá.

**Funciones clave:**
- **Libros/capítulos:** `obtenerBookIdPorSlug`, `obtenerOCrearChapterId`, `buscarChapterId`.
- **Recursos:** `existeRecurso`, `obtenerRecurso`, `obtenerRecursosPorTipo`, `actualizarContenidoRecurso`, `eliminarRecurso`, `publicarRecurso`, `eliminarRecursoExistente`.
- **Guardado:** `guardarRecursoComoBorrador` (publicado=false), `guardarRecursoComoPublicado` (publicado=true), `reemplazarOCrearRecursoPublicado` (upsert inteligente que conserva el `id` y limpia duplicados).
- **Versículos:** `obtenerTextoCapituloCompleto`, `obtenerVersiculo`, `obtenerVersiculoPorSlug`.

**Conexiones:**
- **Es consumido por:** `generarEstudio.js`, `validarEstudio.js`, `aprobarEstudio.js`, `listarImagenesPendientes.js`, `incorporarImagenes.js`, `orquestador.js`, `orquestador-maestro.js`, `generate-prompts.js` (usa su propio cliente, no este).
- **Depende de:** `@supabase/supabase-js`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.

## 6. `src/generarEstudio.js`

**Qué hace:** Orquesta la generación de un **estudio bíblico expositivo** completo.

**Flujo:**
1. Resuelve `bookId` y `chapterId` (crea el capítulo si no existe).
2. Si `forzar=false` y ya existe un estudio → aborta.
3. Lee `prompts/prompt-maestro.txt` (el "system prompt" maestro).
4. Lee indicaciones especiales (`indicacionManual` o `leerIndicacionEspecial`).
5. Trae el texto bíblico real (`obtenerTextoCapituloCompleto`) para evitar alucinaciones.
6. Llama a `generarConDeepSeek` con 32k tokens.
7. Limpia cercas de código (`limpiarCercasDeCodigo`).
8. Valida con `validarEstudio` (mínimo de palabras + tooltips de versículos).
9. Inyecta el **encabezado "Oro Metálico"** (`generarEncabezadoOroMetalico`) con el título extraído.
10. Guarda copia local en `output/<libro>-<cap>.html`.
11. Si pasa validación → `reemplazarOCrearRecursoPublicado` (upsert en Supabase).

**Conexiones:**
- **Entrada:** `prompts/prompt-maestro.txt`, `indicaciones/<libro>.md`, Supabase (`verses`).
- **Salida:** HTML en `output/` + registro en `resources` (publicado=true).
- **Depende de:** `deepseekClient.js`, `leerIndicaciones.js`, `validarEstudio.js`, `supabaseClient.js`.
- **Es consumido por:** `src/cli.js`.

Es el núcleo de integración con Supabase. Expone funciones para:

- **Libros/capítulos:** `obtenerBookIdPorSlug`, `obtenerOCrearChapterId`, `buscarChapterId`.
- **Recursos:** `existeRecurso`, `obtenerRecurso`, `obtenerRecursosPorTipo`, `actualizarContenidoRecurso`, `eliminarRecurso`, `publicarRecurso`, `eliminarRecursoExistente`.
- **Guardado:** `guardarRecursoComoBorrador` (publicado=false), `guardarRecursoComoPublicado` (publicado=true), `reemplazarOCrearRecursoPublicado` (upsert inteligente que conserva el `id` y limpia duplicados).
- **Versículos:** `obtenerTextoCapituloCompleto`, `obtenerVersiculo`, `obtenerVersiculoPorSlug`.

Todo el resto del sistema depende de este módulo.

---

## 2. Capa de dominio / lógica de negocio — `src/`

- **`generarEstudio.js`**: orquesta la generación de un estudio (recibe libro, capítulo, video, mínimo de palabras, forzar, indicación manual).
- **`promptsRecursos.js`**: construye los prompts para cada tipo de recurso (con reglas de ortografía, recorte defensivo de fuentes largas, clases CSS).
- **`formateadores.js`**: convierte los JSON devueltos por la IA en HTML para cada tipo de recurso (ilustraciones, citas, quiz, infografía, paralelos, profecías, conexiones AT/NT, cronología, palabras clave). Incluye `escapeHtml` y `limpiarHtml`.
- **`validarEstudio.js`**: valida el HTML generado y agrega tooltips de versículos en prosa (usa `librosBiblia.js` para resolver referencias).
- **`librosBiblia.js`**: mapa de nombres/slugs de libros bíblicos con normalización de tildes y variantes.
- **`aprobarEstudio.js`**: cambia el estado de un estudio a aprobado/publicado.

---

## 3. Capa de imágenes

- **`extraerImagenesSugeridas.js`**: parsea los comentarios `<!-- IMAGEN_SUGERIDA... -->` del HTML.
- **`listarImagenesPendientes.js`**: lista las imágenes que faltan incorporar.
- **`incorporarImagenes.js`** + **`incorporarImagenesEnHtml.js`**: reemplazan los marcadores por `<img>` reales.

---

## 4. Capa CLI — `src/cli*.js`

Cada comando tiene su propio entrypoint (`cli.js`, `cliAprobar.js`, `cliImagenesPendientes.js`, `cliIncorporarImagenes.js`). Todos comparten el mismo patrón de parseo de argumentos `--clave=valor`.

---

## 5. Scripts auxiliares — `scripts/`

- **`construir-base-ilustraciones.js`**: ingesta PDFs/TXT de clásicos (Spurgeon, Moody, etc.), los divide en bloques y los estructura con IA.
- **`generate-prompts.js`**: genera prompts para NotebookLM a partir de los recursos de un capítulo (incluye mapas con Google Maps embed).
- **`generar-imagenes.js` / `regenerar-imagen.js`**: descargan imágenes generadas por IA.
- **`generar-miniatura.js` / `generar-fondo-miniatura.js`**: generan miniaturas con canvas y fondos con fal.ai.

---

## 6. Capa multimedia

- **`audio-tts/generar-audio.js`**: sintetiza SSML con Google TTS, controla cuota mensual en Supabase (`uso_mensual_tts`), une WAVs y masteriza con ffmpeg.
- **`video/ensamblar-video.js`**: arma el video final con efecto Ken Burns, concatena clips y agrega el audio.

## Detalle de los archivos principales

### `scripts/generate-prompts.js`

**Qué hace:** Es el generador de "prompts para NotebookLM" a partir de los recursos ya guardados en Supabase de un capítulo. Es un módulo **exportable** (`generarPromptsCapitulo(bookSlug, chapterNumber)`) pensado para ser invocado por un orquestador.

**Flujo interno:**

1. `fetchChapterResources` → busca el libro por slug y el capítulo por número en Supabase.
2. `getResourcesForChapter` → trae todos los recursos del capítulo (`estudio`, `sermon`, `bosquejo`, `infografia`, `contexto_arqueologico`, `palabras_clave`, `citas_teologos`, `citas_libros`).
3. `buildPlainTextSource` → arma un `.txt` consolidado (limpia HTML con `cleanHtml`) para subir a NotebookLM.
4. `buildPrompts` → construye 8 prompts distintos:
   - `prompt_video` (estilo visual + narrativo)
   - `prompt_mapa` (mapa mental)
   - `prompt_diapositivas`
   - `prompt_miniatura` (en inglés, para Midjourney/DALL-E)
   - `prompt_descripcion` (SEO YouTube)
   - `prompt_mapa_interactivo` (JSON con ubicaciones geográficas)
   - `prompt_podcast_guion`
5. `generateWithAI` → llama a DeepSeek con `response_format: json_object`.
6. `saveFilesLocally` → escribe archivos numerados `1_VIDEO_...txt`, `2_MAPA_MENTAL_...txt`, etc. en `prompts_output/<libro>/Capitulo_<n>/` con BOM UTF-8.
7. Para el mapa interactivo, `generateMapResourceHTML` genera HTML con `<iframe>` de Google Maps embebido.
8. **Al final** llama a `generarArtefactosVideo` (función interna) que:
   - Genera `prompts_imagenes_video.json` (12 prompts en inglés para Flux/Midjourney).
   - Genera `guion_video_tts.ssml` (guion SSML con 12 marcas `<mark name="imagen_N"/>` para sincronizar con las imágenes).

**Conexiones:**

- **Entrada:** Supabase (`books`, `chapters`, `resources`).
- **Salida:** archivos en `prompts_output/` que consumen los scripts de imágenes, miniatura y video.
- **Depende de:** `@supabase/supabase-js`, `openai` (SDK apuntando a DeepSeek), `fs`, `path`.
- **Es consumido por:** el orquestador (probablemente `src/orquestador-maestro.js`).

### `scripts/generar-fondo-miniatura.js`

**Qué hace:** Genera la **ilustración de fondo** de la miniatura de YouTube usando **fal.ai** (`fal-ai/flux/dev`). No agrega texto: solo la imagen base.

**Flujo:**

1. Lee `prompts_output/<libro>/Capitulo_<n>/youtube_metadata.json`.
2. Extrae `meta.miniatura.prompt_ilustracion`.
3. Llama a `fal.subscribe` con `image_size: 1280x720`, `num_inference_steps: 28`, `guidance_scale: 3.5`.
4. Descarga la imagen resultante y la guarda como `miniatura_fondo.png`.
5. Reintenta 1 vez si falla.

**Conexiones:**

- **Entrada:** `youtube_metadata.json` (generado por el orquestador, no por `generate-prompts.js`).
- **Salida:** `miniatura_fondo.png` → consumido por `generar-miniatura.js`.
- **Depende de:** `@fal-ai/client`, `FAL_KEY` en `.env`.

### `scripts/generar-miniatura.js`

**Qué hace:** Compone la **miniatura final de YouTube** (1280×720, JPG < 2 MB) superponiendo texto sobre la ilustración de fondo, usando `@napi-rs/canvas`.

**Flujo:**

1. Lee `youtube_metadata.json` → `meta.miniatura` (`etiqueta`, `texto_principal`, `texto_secundario`, `lado_texto`).
2. Busca `miniatura_fondo.(png|jpg|jpeg|webp)` en la carpeta del capítulo.
3. Registra la fuente `Anton-Regular.ttf` desde `assets/fonts/`.
4. Compone:
   - Fondo con `cover` + filtro `contrast/saturate`.
   - Degradado lateral + viñeta.
   - Etiqueta superior ("ESTUDIO DE <LIBRO> <CAP>").
   - Texto principal grande con relieve 3D y contorno negro.
   - Franja roja inclinada con texto dorado (complemento).
5. Ajusta tamaño de fuente dinámicamente (`ajustar`) para que quepa en 1 o 2 líneas.
6. Exporta JPG bajando calidad hasta quedar bajo 1.9 MB.

**Conexiones:**

- **Entrada:** `youtube_metadata.json` + `miniatura_fondo.png`.
- **Salida:** `miniatura.jpg` (lista para subir a YouTube).
- **Depende de:** `@napi-rs/canvas`, `assets/fonts/Anton-Regular.ttf`.
- **Acepta overrides por CLI:** `--fondo`, `--principal`, `--secundario`, `--etiqueta`.

### `video/ensamblar-video.js`

**Qué hace:** Ensambla el **video final** (MP4) a partir de las imágenes generadas + el audio TTS, con efecto **Ken Burns** (zoom/pan) por imagen.

**Flujo:**

1. Detecta FFmpeg portable en `tools/ffmpeg/...` (solo Windows).
2. Lee:
   - `audio-tts/guion_video_tts_final.mp3`
   - `audio-tts/guion_video_tts_timestamps.json` (marcas `imagen_N` → segundos)
   - `prompts_output/<libro>/Capitulo_<n>/imagenes/imagen_N.(png|jpg|webp)`
3. Calcula duración de cada imagen a partir de las marcas (la última se ajusta a la duración real del audio vía `ffprobe`).
4. `generarClipKenBurns` → por cada imagen, aplica `zoompan` en 3 fases (apertura rápida → pausa → zoom lento → cierre rápido) a 1920×1080, 24 fps, H.264.
5. `concatenarClips` → usa `concat` demuxer con `-c copy`.
6. `agregarAudio` → mezcla el MP3 con `-c:a aac -b:a 192k -shortest`.
7. Limpia temporales.

**Conexiones:**

- **Entrada:** audio TTS + timestamps + imágenes.
- **Salida:** `prompts_output/<libro>/Capitulo_<n>/video/video_final.mp4`.
- **Depende de:** `fluent-ffmpeg`, FFmpeg (portable o del sistema).
- **Consume indirectamente:** las marcas `<mark name="imagen_N"/>` que genera `generate-prompts.js` en el SSML, y los `prompts_imagenes_video.json` que alimentan a `scripts/generar-imagenes.js`.

### `src/generarEstudio.js`

**Qué hace:** Orquesta la generación de un **estudio bíblico expositivo** completo.

**Flujo:**

1. Resuelve `bookId` y `chapterId` (crea el capítulo si no existe).
2. Si `forzar=false` y ya existe un estudio → aborta.
3. Lee `prompts/prompt-maestro.txt` (el "system prompt" maestro).
4. Lee indicaciones especiales (`indicacionManual` o `leerIndicacionEspecial`).
5. Trae el texto bíblico real (`obtenerTextoCapituloCompleto`) para evitar alucinaciones.
6. Llama a `generarConDeepSeek` con 32k tokens.
7. Limpia cercas de código (`limpiarCercasDeCodigo`).
8. Valida con `validarEstudio` (mínimo de palabras + tooltips de versículos).
9. Inyecta el **encabezado "Oro Metálico"** (`generarEncabezadoOroMetalico`) con el título extraído.
10. Guarda copia local en `output/<libro>-<cap>.html`.
11. Si pasa validación → `reemplazarOCrearRecursoPublicado` (upsert en Supabase).

**Conexiones:**

- **Entrada:** `prompts/prompt-maestro.txt`, `indicaciones/<libro>.md`, Supabase (`verses`).
- **Salida:** HTML en `output/` + registro en `resources` (publicado=true).
- **Depende de:** `deepseekClient.js`, `leerIndicaciones.js`, `validarEstudio.js`, `supabaseClient.js`.
- **Es consumido por:** `src/cli.js`.

### `src/promptsRecursos.js`

**Qué hace:** Es la **fábrica de prompts** para cada tipo de recurso derivado del estudio. Exporta `generarPromptRecurso(tipo, libro, capitulo, textoCapitulo, materiales, baseIlustraciones)`.

**Tipos soportados:**

- `sermon` → sermón homilético con diseño HTML rico (cajas de colores, ilustraciones, notas teológicas).
- `bosquejo` → esquema en "línea de tiempo vertical".
- `aplicaciones_practicas` → tarjetas de acciones concretas.
- `citas_autoridades` → citas de teólogos reales.
- `quiz`, `glosario`, `palabras_clave`.
- `contexto_arqueologico` → "ficha de museo".
- `ilustraciones` → selecciona de una base de datos JSON.

**Reglas transversales:**

- `reglaOrtografia` (español perfecto, sin inventar citas).
- `PERFIL_DOCTRINAL` (monoteísmo puro, sin Trinidad, fórmulas aprobadas sobre el Cordero).
- `recortarFuente` (recorta HTML a 26k chars para no inflar el prompt).
- Prohibición de clases CSS: solo estilos inline.

**Conexiones:**

- **Es consumido por:** `src/orquestador.js` y `src/orquestador-maestro.js`.
- **Depende de:** nada externo (función pura).
- **Su salida** (JSON) se pasa a `formateadores.js` para convertirse en HTML.

### `src/formateadores.js`

**Qué hace:** Convierte los **JSON devueltos por la IA** en **HTML estilizado** con el "Sistema de Diseño Unificado Mahanaim".

**Funciones:**

- `escapeHtml`, `limpiarHtml` (detecta si el HTML ya viene estructurado y no lo re-envuelve).
- `formatIlustracionesHomileticas` → tarjetas premium con cita + conexión + aplicación.
- `formatCitasHtml` → grid de citas con comilla decorativa.
- `formatQuizInteractivo` → quiz con `<script>` inline que valida respuestas.
- `formatTablaGenerica` → tabla responsive.
- `formatInfografiaDoctrinal` → grid con acordeón (mobile) / expandido (desktop).
- `formatParalelosCards`, `formatProfeciasCards`, `formatConexionesCards`, `formatCronologiaCards` → todas con el mismo patrón de acordeón responsive.
- `formatPalabrasClaveHtml` → tarjetas con Strong.
- `formatearRecurso(tipo, datos)` → **router principal**: si `datos.contenido_html` existe, lo usa; si no, delega al formateador específico.

**Conexiones:**

- **Es consumido por:** `src/orquestador.js` / `orquestador-maestro.js` (después de recibir el JSON de la IA).
- **Depende de:** nada externo.
- **Su salida** se guarda en Supabase vía `supabaseClient.js`.

## Observaciones sobre el acoplamiento

1. **`generate-prompts.js` es un caso especial**: crea su **propio cliente Supabase** en vez de usar `src/supabaseClient.js`. Es la única pieza que duplica esa responsabilidad.
2. **`youtube_metadata.json`** es el contrato entre el orquestador y los dos scripts de miniatura. No lo genera `generate-prompts.js` (que genera `prompt_miniatura` en un `.txt`), sino el orquestador maestro.
3. **`guion_video_tts.ssml`** es el contrato entre `generate-prompts.js` y `audio-tts/generar-audio.js` (que produce el MP3 + timestamps).
4. **`prompts_imagenes_video.json`** es el contrato entre `generate-prompts.js` y `scripts/generar-imagenes.js`.
5. **`imagen_N.png`** es el contrato entre `generar-imagenes.js` y `ensamblar-video.js`.
6. **`miniatura_fondo.png`** es el contrato entre `generar-fondo-miniatura.js` y `generar-miniatura.js`.

Todo el pipeline está unido por **archivos en disco** dentro de `prompts_output/<libro>/Capitulo_<n>/`, lo cual es simple pero frágil: si un paso falla, los siguientes no tienen validación de "input listo" más allá de `fs.existsSync`.

// PARTIR UN TURNO EN TROZOS VÁLIDOS PARA LA API
// ============================================================
function partirTextoEnTrozos(texto, limiteBytes = LIMITE_BYTES_POR_LLAMADA) {
  const trozos = [];
  let actual = "";

  // Partimos por oraciones para no cortar palabras al medio.
  const oraciones = texto.split(/(?<=[.!?…])\s+/);

  for (const oracion of oraciones) {
    const candidato = actual ? `${actual} ${oracion}` : oracion;
    if (Buffer.byteLength(candidato, "utf-8") > limiteBytes && actual) {
      trozos.push(actual);
      actual = oracion;
    } else {
      actual = candidato;
    }
  }
  if (actual) trozos.push(actual);

  // Si alguna oración sola excede el límite, la partimos por palabras.
  const finales = [];
  for (const trozo of trozos) {
    if (Buffer.byteLength(trozo, "utf-8") <= limiteBytes) {
      finales.push(trozo);
      continue;
    }
    let acumulado = "";
    for (const palabra of trozo.split(/\s+/)) {
      const cand = acumulado ? `${acumulado} ${palabra}` : palabra;
      if (Buffer.byteLength(cand, "utf-8") > limiteBytes && acumulado) {
        finales.push(acumulado);
        acumulado = palabra;
      } else {
        acumulado = cand;
      }
    }
    if (acumulado) finales.push(acumulado);
  }
  return finales;
}

// WAV: lectura y unión
// ============================================================
function leerDatosWav(buffer) {
  const indiceData = buffer.indexOf("data");
  const inicioDatos = indiceData + 8;
  const sampleRate = buffer.readUInt32LE(24);
  const numCanales = buffer.readUInt16LE(22);
  const bitsPorMuestra = buffer.readUInt16LE(34);
  const datosPCM = buffer.slice(inicioDatos);
  const duracionSegundos =
    datosPCM.length / (sampleRate * numCanales * (bitsPorMuestra / 8));
  return { datosPCM, sampleRate, numCanales, bitsPorMuestra, duracionSegundos };
}

function unirWavs(buffers) {
  const partes = buffers.map(leerDatosWav);
  const totalDatos = Buffer.concat(partes.map((p) => p.datosPCM));

  const primerBuffer = buffers[0];
  const indiceData = primerBuffer.indexOf("data");
  const encabezado = Buffer.from(primerBuffer.slice(0, indiceData + 8));

  encabezado.writeUInt32LE(36 + totalDatos.length, 4);
  encabezado.writeUInt32LE(totalDatos.length, indiceData + 4);

  const duracionTotal = partes.reduce((acc, p) => acc + p.duracionSegundos, 0);

  return { wavFinal: Buffer.concat([encabezado, totalDatos]), duracionTotal };
}

/**
 * Genera un WAV de silencio con el mismo formato que el WAV de referencia
 * (sample rate, canales, bits por muestra).
 */
function generarSilencioWav(referenciaWav, duracionMs) {
  const { sampleRate, numCanales, bitsPorMuestra } = leerDatosWav(referenciaWav);
  const bytesPorMuestra = bitsPorMuestra / 8;
  const numMuestras = Math.round((sampleRate * duracionMs) / 1000);
  const tamanoDatos = numMuestras * numCanales * bytesPorMuestra;

  const encabezado = Buffer.alloc(44);
  encabezado.write("RIFF", 0);
  encabezado.writeUInt32LE(36 + tamanoDatos, 4);
  encabezado.write("WAVE", 8);
  encabezado.write("fmt ", 12);
  encabezado.writeUInt32LE(16, 16);
  encabezado.writeUInt16LE(1, 20); // PCM
  encabezado.writeUInt16LE(numCanales, 22);
  encabezado.writeUInt32LE(sampleRate, 24);
  encabezado.writeUInt32LE(sampleRate * numCanales * bytesPorMuestra, 28);
  encabezado.writeUInt16LE(numCanales * bytesPorMuestra, 32);
  encabezado.writeUInt16LE(bitsPorMuestra, 34);
  encabezado.write("data", 36);
  encabezado.writeUInt32LE(tamanoDatos, 40);

  const datos = Buffer.alloc(tamanoDatos, 0);
  return Buffer.concat([encabezado, datos]);
}

const FILTROS_EQ_COMPRESION = [
  "highpass=f=65",
  "equalizer=f=6500:width_type=o:width=1.2:g=-3",
  "equalizer=f=200:width_type=o:width=1.5:g=1.5",

];

const LOUDNORM_TARGET = { I: -16, TP: -1, LRA: 7 };

function medirLoudness(rutaEntrada) {
  return new Promise((resolve, reject) => {
    let stderr = "";
    ffmpeg(rutaEntrada)
      .audioFilters([
        ...FILTROS_EQ_COMPRESION,
        `loudnorm=I=${LOUDNORM_TARGET.I}:TP=${LOUDNORM_TARGET.TP}:LRA=${LOUDNORM_TARGET.LRA}:print_format=json`,
      ])
      .outputOptions(["-f null"])
      .output(process.platform === "win32" ? "NUL" : "/dev/null")
      .on("stderr", (line) => {
        stderr += line + "\n";
      })
      .on("end", () => {
        const match = stderr.match(/\{[\s\S]*?"input_i"[\s\S]*?\}/);
        if (!match) {
          return reject(
            new Error("No se pudo parsear la medición de loudnorm (pasada 1)."),
          );
        }
        try {
          resolve(JSON.parse(match[0]));
        } catch (err) {
          reject(
            new Error(`JSON de loudnorm inválido: ${err.message}\n${match[0]}`),
          );
        }
      })
      .on("error", (err) => {
        reject(new Error(`Error de FFmpeg en pasada 1 (medición): ${err.message}`));
      })
      .run();
  });
}

function aplicarLoudnorm(rutaEntrada, rutaSalida, medicion) {
  return new Promise((resolve, reject) => {
    const filtroLoudnorm =
      `loudnorm=I=${LOUDNORM_TARGET.I}:TP=${LOUDNORM_TARGET.TP}:LRA=${LOUDNORM_TARGET.LRA}` +
      `:measured_I=${medicion.input_i}` +
      `:measured_TP=${medicion.input_tp}` +
      `:measured_LRA=${medicion.input_lra}` +
      `:measured_thresh=${medicion.input_thresh}` +
      `:offset=${medicion.target_offset}` +
      `:linear=true`;

    ffmpeg(rutaEntrada)
      .audioFilters([...FILTROS_EQ_COMPRESION, filtroLoudnorm])
      .audioCodec("libmp3lame")
      .audioBitrate("192k")
      .audioFrequency(44100)
      .outputOptions(["-ar 44100", "-b:a 192k"])
      .save(rutaSalida)
      .on("end", () => {
        console.log(`✅ Audio masterizado: ${rutaSalida}`);
        resolve();
      })
      .on("error", (err) => {
        reject(new Error(`Error de FFmpeg en pasada 2 (aplicación): ${err.message}`));
      });
  });
}

async function sintetizarTexto(texto, voz) {
  const respuesta = await fetch(
    `https://texttospeech.googleapis.com/v1beta1/text:synthesize?key=${API_KEY}`,
    {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        input: { text: texto },
        voice: { languageCode: IDIOMA, name: voz },
        audioConfig: { audioEncoding: "LINEAR16" },
      }),
    },
  );

  if (!respuesta.ok) {
    const errorTexto = await respuesta.text();
    throw new Error(
      `Error de la API de Google (${respuesta.status}): ${errorTexto}`,
    );
  }

  const datos = await respuesta.json();
  return Buffer.from(datos.audioContent, "base64");
}

async function sintetizarTurno(turno) {
  const voz = turno.speaker === "B" ? VOZ_B : VOZ_A;
  const trozos = partirTextoEnTrozos(turno.texto);
  const buffers = [];

  for (const trozo of trozos) {
    const buf = await sintetizarTexto(trozo, voz);
    buffers.push(buf);
  }

  if (buffers.length === 1) return buffers[0];
  return unirWavs(buffers).wavFinal;
}
